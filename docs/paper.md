# 本地 Paper 账户 MVP

本文描述 M1 单标的历史引擎；M3 持续多标的账户和真实观察时序见 [运行说明](forward.md)。

目标是验证“行情 → 信号 → 成交 → 账户 → 风险 → 报告”的完整流程。
首版不连接任何券商，也不调度真实资金。账户初始资金默认 5,000 美元。

## 信号与成交

信号使用原始收盘价加截至当日已除息的累计每股现金分红，构造不再投资分红的连续收益
序列。该值高于包含当日在内的 N 日简单均线且空仓时，按原始收盘价和目标仓位计算整股
订单；持仓时不高于均线则退出。拆股同时缩放历史信号与累计每股分红，不提前使用未来事件。

订单只在下一 XNYS 交易日开盘有效，节假日不占用有效期；错过该交易日即记录过期，
不会在数天后按旧信号补成交。当前完整日线模型中，只要该日输入有效，就以供应方日线
开盘价作为成交代理；它不证明真实开盘拍卖价、流动性或可成交性。跳空导致买不起时缩减
整股数量，仍买不起则拒单，日终可按新信息产生新的决定。最后一天的订单保留待下次更新。

每笔成交扣固定费用。买入成交价上浮、卖出下浮指定基点；所有交易决策日期和成交日期
分开记录。股数预算在前一收盘产生，不能因已知第二天上涨而扩大订单。
不模拟盘口、容量约束、盘中止损触达或真实部分成交。整日成交量不参与开盘撮合；
零成交量使整段历史不通过质量准入，不是利用当天收盘信息选择性跳过某笔开盘交易。

日终净值 = 现金 + 持仓数量 × 原始收盘价 + 尚未支付的分红应收款。
所有费用计入净值，期末浮动盈亏不能被遗漏。基准从相同预热期结束后的下一交易日
开盘开始买入，采用相同仓位预算和成本，此后持续持有，不采用策略风控退出。
当前现金口径为交易日记账、无外部入金/出金，不模拟 T+1 结算、税款、利息或现金账户
交易限制；不能把模拟可用现金直接映射成嘉信实际购买力。

## 研究默认值

| 项目 | 默认值 | 性质 |
| --- | --- | --- |
| 初始资金 | 5,000 美元 | 项目起点 |
| 均线窗口 | 20 日；演示配置 5 日 | 待验证的研究参数 |
| 单标的资金分配 | 80% | 待验证的研究参数，仅开仓时约束 |
| 每单费用 | 1 美元 | 模拟假设，不代表嘉信或 Alpaca 费率 |
| 单向滑点 | 5 基点 | 模拟假设 |
| 单仓止损 | 成本回撤 8% | 待验证的研究参数 |
| 单仓利润回撤 | 持有期含已获分红的每股价值高点回撤 12% | 待验证的研究参数 |
| 账户利润回撤 | 账户日终净值高点回撤 15% | 待验证的研究参数 |
| 本金警戒 | 低于初始本金的 80% | 交接中记录的硬边界 |
| 项目终止 | 不高于初始本金的 50% | 交接中记录的硬边界 |

单仓成本包含买入费用。止损和利润保护比较“原始收盘价 + 本次持仓已获得的每股分红”
与成本/持有期高点，避免机械除息误触发退出；未支付分红同样计入经济价值，但不成为可用
现金。卖出后清零本仓分红累计，新仓重新起算。会计中的实际成本、现金和应收不因信号
调整被改写。账户保护继续使用完整净值，真实损失和跳空仍能触发退出。

## 风险状态

- `active`：允许按策略开仓或退出。
- `warning`：低于本金警戒线后停止新开仓、安排下一可成交开盘退出，等待人工复核。
- `halted`：账户高点回撤触发停用，同样安排退出。
- `terminated`：达到本金终止线，取消开仓并安排清仓。

终止状态优先级最高，其次是账户回撤停用。即使已经停用，跌破本金警戒线也会单独
记录事件。所有非 active 状态均保留，不会因盈利反弹、账户清空或程序重启自动恢复。
首版没有“恢复交易”按钮；新目录只用于独立研究，不能用来恢复已停用的持续资金账户。
持续账户的恢复和跨版本迁移属于 M3；不得通过重启绕过风险状态。

规则均按日终观测、后续开盘执行。跳空、缺失行情或无成交量可能造成更大损失；
2,500 美元是触发边界，不是保本成交价。单仓退出后允许后续新信号重新开仓；
账户级停用则保持。警戒后的动作及上述研究参数是当前实现选择，不等于用户已经批准实盘。

## 重启与一致性

每次从累计原始数据重放相同会计引擎，随后生成完整的不可变快照。相同输入不新增快照；
追加数据的结果必须与一次性完整重放一致。源码校验值、配置、输入文件校验值和版本
记录在 Parquet 中。文件锁阻止并发更新，所有文件和图表成功写出后才原子切换 CURRENT。
更新失败时旧快照仍是当前状态；这不替代磁盘备份或断电耐久性保障。

`paper` 更新前强制执行日历和数据质量检查。真实输入须通过 `--dataset` 校验原始响应、
参数、文件校验值和标准化结果。`--require-current` 检查最近可接纳交易日是否齐全；
Alpaca 日线需到次日纽约时间 00:15 后才能接纳，半日市不提前。
失败时拒绝更新、保留原快照，数据修复后才能重试。这是更新流程的暂停，不会伪造缺失日
的估值或把原账户改成新的风险状态，也不表示已有订单在真实市场中得到执行。

`reconciliation.parquet` 从成交、原始价格、拆股和分红独立重建现金/持仓/应收/净值，
同时检查决策时序、成交费用和基准净值。任何不一致阻止快照发布。真实批次完整复制到
快照的 `dataset/`，数据修订产生新批次；只有既有数据行和来源/feed 等稳定口径不变时
才能接续同一账户。仅获取时间和批次编号改变、价格/事件完全相同时，不新增成交。

指定 `--dividend-source` 时，发行方现金分红核对也必须通过；来源和核对表一起存入快照，
不得在重启时悄悄省略或替换。此核对不覆盖其他行动或历史发布时间。

本文的 `paper` 命令仍为单账户单标的；SPY 2024 年及 2021—2025 年真实试读、分红核对和回放已验收。
M2 的 `research` 命令已支持多标的共享现金及独立历史实验，见 [研究说明](research/README.md)。
它复用本节成交/行动会计，增加加仓加权成本、部分卖出与组合风险；实时调度和券商订单属于后续阶段。

## Alpaca 的使用时机

先通过真实历史数据检验模型，并用本地账户逐日追加行情观察信号与风险行为。
当需要测试外部订单生命周期、网络断连重试、撤单和成交核对时，再接 Alpaca paper。
届时保留本地账本作为核对基准。Alpaca 的成交模拟及权限也不能代替嘉信账户验证。
演示与离线验证不需要 API 凭据。M1 的 Alpaca Market Data 读取需要凭据，
只使用行情域名，不依赖向 Alpaca paper 提交订单。
