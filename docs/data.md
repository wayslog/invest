# Parquet 数据约定

所有数据表使用 Parquet 和 Zstandard 压缩。不能通过文件扩展名伪装格式；输入会验证
Arrow 类型、日期、价格、企业行动和来源元数据。金额/原始价格采用 `decimal128(24, 6)`，
会计运算使用 Decimal；收益和绘图可使用浮点数。

## Paper 日线：invest.bars.v1

目前每个文件只包含一个标的、每个交易日一行；列顺序和类型必须与下表一致。

| 字段 | Arrow 类型 | 含义 |
| --- | --- | --- |
| date | date32 | 美东交易日；非 UTC 时间戳 |
| symbol | string | 必须与账户配置一致 |
| open / high / low / close | decimal128(24, 6) | 未复权原始 OHLC，美元，严格为正 |
| volume | int64 | 当日成交量，非负；为零时整段历史不通过回放准入 |
| split_ratio | int64 | 当日开盘前正向拆股倍数；无拆股填 1 |
| dividend | decimal128(24, 6) | 当日除息、每股现金分红；无分红填 0 |
| dividend_pay_date | date32，可空 | 实际支付日；无分红时为空 |

必须包含 Parquet schema 元数据：

```text
schema_version = invest.bars.v1
price_basis = raw
currency = USD
session_timezone = America/New_York
source = synthetic 或明确的数据提供者名称
```

代码可复用 `invest.market.BAR_SCHEMA` 构造表。`examples/generate.py` 给出完整写入示例。
如果分红和拆股发生在同一天，dividend 按拆股后的每股口径提供。仅前一交易日已持有的
股票获得分红；除息日开盘新买入的不获得。支付日遇到无输入记录的日期，在下一条日线
到来时入账；应收期间计入净值但不能用于买入。

拆股仅在发生日调整持仓、待成交数量和此前已知价格序列，不提前用未来拆股信息。
首版不支持反向拆股、分数股现金替代、股票分红、并购和退市清算；不能把这些事件填 1
或 0 静默略过。数据提供者必须核实企业行动后再导入。

`paper` 强制校验交易所日历、唯一递增日期、完整区间、已收盘状态和非零成交量。
真实输入必须使用经过验证的 `--dataset`；`--data` 只接受明确标记的人工样例。
所有检查均不补齐或改写行情；`audit` 仍可单独运行，以保存错误明细。
数据源名称属于可追踪信息，不等于已经完成真实性或时点正确性验证。

## 交易日历与质量报告

```bash
uv run --locked invest audit \
  --data examples/paper_bars.parquet \
  --symbol DEMO \
  --start 2024-01-02 --end 2024-02-13 \
  --as-of 2024-02-14T00:00:00Z \
  --output reports/quality/demo.parquet
```

日期范围包含首尾两天，必须显式提供，以发现开头或结尾缺失的记录。`as-of` 必须包含
时区；它是本次检查采用的时间截点，不会自动取当前时间，也不是数据的真实获取时间。
质量报告使用 `invest.quality.v1`，列为 `status`、`check`、可空的 `date` 和 `detail`；
元数据记录输入 SHA-256、标的、检查范围、时间截点及日历库版本。
结果为 Parquet/Zstandard，输出文件已存在时拒绝覆盖，需要另选文件名。

当前使用锁定版本的 `exchange-calendars` XNYS 常规交易时段，处理节假日、已收录的临时
休市、半日市和夏令时；开收盘时间为 UTC，不包含盘前盘后。这里只使用 XNYS 时段作为
首个美国 ETF 研究范围的日历基准，其他交易所和品种需另行核实，未来临时休市仍需更新日历。

| 结果 | 检查与含义 |
| --- | --- |
| error | 类型、价格、企业行动字段或排序不符合 `invest.bars.v1` |
| error | 已收盘的预期交易日缺失，包括范围首尾；非交易日或范围外有记录 |
| error | 范围内有截至 `as-of` 尚未收盘的交易日，或范围内没有交易日 |
| error | Alpaca 日线尚未达到次日纽约时间 00:15 的保守采集门槛；半日市也不提前接纳 |
| error | 零成交量历史不能支持当前日线开盘价代理；拒绝整段回放，不按未来整日量选择性撮合 |
| warning | 人工样例只用于工程测试 |
| warning | 数据实际发布/最终确认时间未验证；日历收盘不代表行情已发布 |
| warning | 企业行动的完整性未验证；字段合法不代表事件没有遗漏 |
| warning | Alpaca 日线是供应方聚合口径，成交量不能作为常规时段成交量，开盘价是历史成交代理 |

退出码 `0` 表示当前结构和日历检查无错误，仍可能有上述警告；`1` 表示检查发现错误，
详细报告仍会保存；`2` 表示参数、文件读写或执行失败。命令标准输出只是 JSON 摘要，
报告表保存在指定 Parquet 文件。

样例应得到 **0 个错误、3 个警告**，仅验证工程行为。真实数据还需批次校验和外部事件
核对；当前结构报告不能单独作为准入证明。M1 的已验收范围与明确限制见验收记录。

Alpaca 日线的门槛是工程选择，覆盖可能跨越常规收盘的整日数据更新，并预留 15 分钟；
不是供应方发布时间承诺。批次还逐页检查行情响应的收到时间，不能用较晚收到的企业行动
响应把提前抓取的行情变成已完整日线。后续修订仍产生新批次，不宣称历史数据永不变化。

## 单序列分析

`invest analyze` 读取两列：`date: date32` 和数值型 `adjusted_close`，至少两行。
用于价格序列收益/回撤分析，不能作为 paper 账户的成交输入。调整口径由上游负责；
代码不会根据普通收盘价推断分红再投资收益。`examples/prices.parquet` 是人工样例。

## 真实行情批次：invest.dataset.v2

`invest fetch` 只访问 Alpaca 行情域名的两个 GET 端点，显式指定 `raw`、feed、区间和排序。
分别完整遍历日线与所有类型企业行动的分页。请求超时、认证失败、分页截断、未知事件、
缺失支付日、分数比例/反向拆股、特殊或境外分红、due-bill 事件、同日多事件均拒绝准入。
同日多事件的先后和每股口径需额外核实，因此不能自动合并。当前不支持的退市、并购等
只要出现在供应方结果中就会拒绝；供应方完全遗漏的事件仍需外部核对。

企业行动接口的请求日期不能当作除息日范围。当前从 `1970-01-01` 查询至捕获时冻结的
`actions_through`，保留供应方实际返回的全部处理记录，再按 `ex_date` 选择研究区间。
因此区间前除息、区间内支付的分红不产生新账户权益；区间内除息、次年支付的分红仍计
应收。宽查询不保证供应方覆盖全部历史，捕获截点之后才处理的事件仍属未知。

每次采集生成 `data/alpaca/<批次编号>/`，不覆盖已有文件：

| 文件 | 内容 |
| --- | --- |
| raw.parquet | 逐页端点、查询参数、收到响应的 UTC 时间、响应 SHA-256 和原始响应字节；不保存认证头 |
| bars.parquet | `invest.bars.v1` 标准化行情，额外标记 feed、批次编号、观察时间和仅限历史研究的范围 |
| actions.parquet | 支持事件的日期、分红/支付日和整数拆股比例；完整原始事件仍保存在 raw 中 |
| availability.parquet | 每条行情的保守观察时间 `observed_at`，取批次最后一页收到的时间；`published_at` 当前为空 |
| quality.parquet | 结构、日历、分页、事件映射结果及未验证事项 |
| manifest.parquet | 标的、区间、feed、企业行动捕获截点、观察时间、标准化版本、研究范围与状态 |
| files.parquet | 其他批次文件的 SHA-256 清单 |

供应方通过 JSON 返回的数据以原始字节嵌入 Parquet，不产生 JSON/CSV 数据文件。
批次准备完毕后重命名发布；途中出错的已取得响应保留在 `quarantined` 批次，可能没有
标准化表，禁止进入回放。认证配置完全缺失时在发请求前退出，不创建假批次。

`research_only` 表示当前供应方捕获、结构和日历检查通过，只允许明确限制的历史研究。
`verify-data` 核对文件清单和校验值，重新执行标准化，并用原始检查时点重验日历；
`paper --dataset` 强制执行该流程，不以文件能够读入作为准入标准。
未知历史发布时间和通用企业行动完整性继续保留警告。发行方现金分红核对是另一个范围
明确的报告，不会将“不知道其他行动是否遗漏”改成“所有企业行动已证实完整”。

`observed_at` 证明本次系统最早何时取得整批信息，不能回填成历史交易日的“当时可用时间”。
当前历史回放假设该版本日线和事件可用于研究，未宣称满足严格历史时点或真实前向交易。
供应方返回的日线 open 是历史撮合代理，不保证常规时段开盘拍卖价；IEX 与 SIP 不自动混用。
数据修订和重新下载各自形成新批次；新旧批次的归因与人工核对仍应保留研究记录。

## 发行方现金分红证据

`capture-dividends` 只读 State Street 公共历史分红表，不使用 Alpaca 凭据。
原始表格响应嵌入 `invest.research.source.v1` Parquet 的二进制 `body`，同时保存 URL、
UTC 观察时间和 SHA-256；不增加 Excel/CSV 账户输入。

`audit-dividends` 离线验证来源身份、校验值、时间和字段布局，按批次标的/除息区间选择
完整事件集合，再比较精确金额和支付日。遗漏、多余、重复、超精度、非零资本利得分配、
未知布局及空参考集均不能被当作通过。当前解析器适用于该发行方表格，不是通用基金接口。
核对报告使用 `invest.dividend_audit.v1`，绑定行情文件、数据批次和来源校验值，输出不覆盖。

`paper --dividend-source` 在创建/更新账户前执行同一核对；不一致时保持原账户状态。
成功后保存来源和核对报告，并再次验证复制后的批次。更换或删除既有来源需要新建研究
账户；相同输入和相同证据重跑仍不新增快照。没有此选项时只提供基础历史研究准入，
报告仍提示需外部核对；M1 正式真实案例均使用此选项。

## 账户数据完整性

每日更新提供完整累计历史。已处理记录、字段类型、来源元数据都不能被悄悄修改；
发现历史修订、引擎变化或参数变化时必须建立新账户进行对照，旧快照保留。
模型和数据变化不可用修改旧账本的方式混入同一条 paper 记录。

## M2 组合研究表

M2 继续使用 `invest.bars.v1`，每个标的单独校验并要求完整且完全相同的 XNYS 会话。
不通过取日期交集隐藏缺失。真实研究还必须通过数据批次复现和发行方现金分红核对；
合成路径显式要求 `source=synthetic`，不授予投资验证资格。

研究登记为 `invest.research_registration.v2`，嵌入原始配置字节、校验值及引擎源码指纹；
新运行和完整回放必须匹配登记的引擎。旧 v1 登记仅供原记录核对，不自动升级。
研究清单为 `invest.study.v2`。持仓/订单/成交含 symbol；总净值只有一份共享现金。
金额继续为 `decimal128(24,6)`，股数/次数为 `int64`，会话日期为 `date32`，
登记和来源时间为带 UTC 时区的微秒时间戳，比率为 `float64`。
相关性未知或零波动时为 null 并拒绝该对增配；无正平仓利润时集中度为 null，
无收益波动时 Sharpe 为 null，不用零冒充可解释的比率。
具体表结构及复现操作见 [研究说明](research/README.md)。

准入表另存 `first_bar_received_at`：对已核验原始批次的所有行情页取最早 `received_at`。
它与表示批次结束时间的 `observed_at` 分开；研究时间门槛要求每个准入标的的最早行情页
严格晚于登记，缺失、相等或更早均不通过。较晚行情页/企业行动响应不能覆盖较早行情事实。
